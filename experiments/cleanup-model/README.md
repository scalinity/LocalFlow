# LocalFlow cleanup-model experiment

Compares LocalFlow's current cleanup model (A, `mlx-community/Qwen3-4B-Instruct-2507-4bit`)
with untuned Qwen3.5-4B (B, `mlx-community/Qwen3.5-4B-4bit`) and Qwen3.5-4B fine-tuned for
LocalFlow cleanup (C). Everything runs through LocalFlow's real `CleanupEngine`, prompts and
validator. The result is `reports/localflow-cleanup-comparison/index.html`.

Run or resume everything (finished Claude batches are never bought twice):

    HF_HOME=~/Documents/LocalAI/models ~/Documents/LocalAI/.venv/bin/python \
        experiments/cleanup-model/run.py all        # or: status, all --dry-run, <stage>

Stages: incumbent, audio, generate, verify, assemble, train, select, export, evaluate, judge,
analyze, report. Settings, model revisions, budgets and the frozen decision rules are in
`config.yaml`. Large files (data, batch manifests, checkpoints, logs) live in the ignored
`artifacts/` folder; models live in `~/Documents/LocalAI/models/hub`. The `report` stage writes the
public report (public-dataset transcripts left out) and a full local copy with every transcript at
`artifacts/report-full/index.html`.

The synthetic data is `PRODUCT_AUTOGENERATED`: Claude-generated and Claude-verified, never
human-reviewed. It does not satisfy, and does not touch, the owner-reviewed M15 corpus rules.

Tests (unittest, script-runnable like the rest of LocalFlow's tests):

    cd experiments/cleanup-model
    for t in tests/test_*.py; do HF_HOME=~/Documents/LocalAI/models HF_HUB_OFFLINE=1 \
        ~/Documents/LocalAI/.venv/bin/python "$t"; done
