Reuse M15's 140 referenced speech clips (60 short / 80 diverse) plus 20
silence/background negatives, its acoustic/context strata, and its referenced
text/transform cases. Inventory retained audio first, then record **only the
missing human strata once**. Human-reviewed references remain truth; saved ASR
output is not a gold reference. Synthetic audio proves mechanics and has a
separate denominator. No physical microphone replay for each candidate.

A read-only setup inventory found 11 WAV assets under existing private evidence.
Their human origin, consent, reference coverage, retention and split eligibility
have not been adjudicated by this setup. Eleven files does not mean eleven
eligible human references. No existing evidence is rewritten or copied here.

The private `m15-frozen-corpus/1` manifest lives beside its relative assets in
`~/Library/Application Support/LocalFlow/v2-evidence/`. Each asset has `path` and
`sha256`; traversal and symlinks inside that corpus are refused. Hashes are
rechecked before every candidate/case/repetition, including resumed units.
`reference_state` must be `frozen`; each case has an explicit reviewed reference.
Changes require a new corpus version and new run directory.

A reference JSON can carry `text`, `correction_spans` and `checks`:
`literals` are exact strings; `required` is a list of alternative-string
groups; `forbidden` lists text that must not appear. These are reviewed
contract assertions, not candidate-specific prompt tuning. Correction spans
refer to the frozen Normalized input. Original references, not candidate
outputs or validator verdicts, determine the gold deletions.

749 legacy candidates. Import the pre-M15 review workstream's frozen output

## Tracks

**Track A — cleanup-only:** PRIMARY quality comparison. Frozen Normalized text
and identical metadata enter the unchanged LocalFlow cleanup engine through
benchmark-side adapters. No ASR or desktop insertion runs. Runtime chat
rendering differs only through each pinned artifact's official template.
Semantic messages and examples remain LocalFlow's versioned messages.

**Track B — end-to-end-audio:** actual same-byte WAV decode, Parakeet inference,
normalization, candidate cleanup and validation in one measured file-replay
pipeline. ASR remains resident beside the cleanup model; report actual
contention/memory. Do not add medians to invent an end-to-end number.
The corpus's `asr` field supplies a pinned repository/revision; it must already
be in the configured cache. The historical Parakeet baseline is
`ed2b7e8c15f9aaa0b5772e2efb986255eaef7e15`; its global-cache artifact was absent
in this setup inventory. Restoring/verifying that ASR condition is a later
replay prerequisite, not a fabricated Track B measurement.

WAVs must be finite mono float32-decodable audio at Parakeet's actual sample
rate. Refuse mismatched formats; never relabel/resample bytes silently.
Protected ranges are mapped through LocalFlow's actual normalization ledger.
If replay ASR produces a different Normalized text, frozen correction offsets
cannot be applied to it: correction-offset metrics stay null with a reason,
while final reference/ASR/normalization lineage remains measurable.
This is file-replay latency, excluding physical mic/device and target insertion.
Those existing M15 measurements remain separate obligations.

## Primary adapters and compatibility

One resident candidate process at a time. Load -> template -> greedy generation
-> validator -> unload -> synchronize/clear resources -> process exit, with
memory captured before load, loaded idle, generation peak and settled state.
Track B also captures the ASR+cleanup peak. Do not keep multiple candidates
resident; don't repeatedly force an OOM.

All candidates use temperature zero, `enable_thinking=False`, LocalFlow's
`min(words*3+96,4096)` window budget and 160-token correction pass. No extended
reasoning, MTP, speculative decoding, tools or candidate-specific semantic
prompt tuning. The official Gemma text path excludes multimodal towers through
the runtime's supported loader; downloaded files remain intact. Its actual
memory is measured, not inferred from the unused tower's disk size.

Reasoning tags in a direct response are a template incompatibility rather
than silently repaired output. Template/message rendering and runtime/config
hashes are recorded. Special semantic tuning would require the separately
reported `NEEDS_MODEL_SPECIFIC_ADAPTATION` disposition, never a hidden Round 1
advantage. A later reasoning or MTP experiment must be a named ablation.

Setup smoke uses one tiny identical Unicode/numeric cleanup input; verifies
load, official system/user template, direct mode, greedy generation, output
extraction, output-limit metadata, validator consumption, runtime identity and
release. It is not a correction/fidelity qualification corpus.

## Metrics, gates and evidence

Each private unit keeps source/reference/final hashes; actual proposals,
accepted/rejected/rolled-back spans, rendered model inputs, windows, component
findings, final output and stage lineage. Public output is an allowlisted
content-free projection. Reports group candidate, track, stratum, length band,
human/synthetic, reference type and split; failed units remain in denominators.

Mechanical fidelity uses LocalFlow validation against the reviewed intended
reference, protected-token/literal/numeric/negation/constraint/technical survival,
structure/list count/order, novelty and answer-vs-edit checks. Record deterministic
failures separately from heuristic findings. These checks do not certify every
possible meaning defect; M07's reviewed real-text and critical human assertions
remain absolute requirements. Report both rejected raw candidates and final
fallback behavior. An unchanged-source model has zero useful-cleanup credit.

Correction counts: opportunities, correct resolutions, safe misses, wrong
corrections, over-deletion, residual markers, fallback-after-correction,
rollback and no-proposal. Match accepted deletion offsets to frozen reviewed
gold; keep precision, recall and exact-reference success separate. Wrong
corrections are a hard failure. A safe miss is not scored as correct. No
reviewed opportunities means null precision/recall, never perfect scores.

Timing: cached cold model load separate from warm first token, generation,
validation, complete cleanup and actual Track B ASR/normalization/end-to-end.
Report n, failures, p50/p95/p99/max; never include downloads/model switches in
ordinary latency. Full M15 requires at least 30 unique cases per latency band
x5 warm runs and ten cached cold processes. Small setup smoke quantiles have
n=1 and cannot support tail-latency or acceptance claims. Qualification reports
identify unique cases/families and failure counts. Quality rate intervals use
a deterministic 200-draw family bootstrap (95% empirical intervals); repeats
are clustered, and fewer than two families has no interval. Zero observed
defects never establishes zero population risk. Rates condition on completed
units; failed units remain explicit counts and block the complete gate.

Memory mechanism: `ps` current process RSS, `resource.ru_maxrss` peak RSS
(macOS bytes), MLX active/cache/peak allocator bytes and `vm_stat` reclaimable
estimate (free+inactive+speculative). RSS and MLX counters overlap: do not sum
as independent RAM. The system estimate is not guaranteed allocation headroom.
The subprocess MLX limit is 72% of physical memory with a 256 MiB cache; a
measured low-headroom/swap-pressure guard can stop only its own worker.
Smoke excludes co-resident ASR and does not prove 48 GB production viability.

`results.json` and `report.md` retain raw counts and explicit nulls, failed
statuses, cold loads, component metrics and cohorts. The comparison table
shows critical/wrong/missed corrections, precision/recall, useful/reject/
fallback/output-limit percentages, constraint/literal/number/structure passes,
cleanup p50/p95, actual end-to-end p95, peak memory and load state. Never
collapse these into one scalar. Supplemental Pareto fronts compare fidelity
vs latency, fidelity vs memory and useful cleanup vs fallback within the same
track and origin; incomplete/failed candidates do not appear as winners.

The 4B 8-bit ablation compares identical frozen inputs with 4B OptiQ for
semantics, corrections, fallback, latency and memory. Extra precision earns
no preference without material fidelity improvement. Qwen3.6 35B-A3B and Gemma
26B-A4B are memory/latency ceilings; report quality gain and each cost separately.
Bigger is not presumed better or safe to ship.

## Resume and failure isolation

Atomic checkpoint key: candidate / case / repetition / track. A resume checks
source/code/runtime/template/model/corpus identity and hashes again, skips
completed units, and retries failed units; `--rerun` deliberately regenerates
completed units. One crash/OOM/timeout cannot erase other candidates' evidence.
Statuses: COMPLETE, LOAD_FAILED, OOM, UNSUPPORTED_ADAPTER,
TEMPLATE_INCOMPATIBLE, TIMEOUT, SKIPPED_BY_CONTRACT. No failure gets invented
quality/latency numbers. A missing measurement stays null with its reason.

A run identity includes source SHA plus source-file digest (including dirty
setup code), benchmark SHA, candidate repository/revision/quantization,
runtime versions, template/config/prompt/correction hashes, corpus/audio hashes,
ASR and normalization identity, reference Mac class and timestamps. A new
identity requires a new run; silent drift invalidates a comparison.

## Promotion and closure

A default replacement requires **all** eleven conditions:

1. Zero critical meaning failures on required frozen acceptance.
2. No protected/literal/numeric/negation safety regression.
3. Zero wrong corrections on critical correction cases.
4. Useful cleanup not materially worse.
5. Explicit acceptable fallback rate.
6. Long-prompt/constraint gates pass.
7. M07 reviewed real-text qualification passes.
8. The packaged offline adapter loads.
9. Latency fits the budget or the owner explicitly accepts the tradeoff.
10. Measured memory leaves safe headroom for Parakeet+LocalFlow+macOS.
11. The owner explicitly approves changing the production default.

After candidate comparison: selected model -> M07-V001 model-dependent rerun
-> reuse the compatible M07-V002 frozen real-text set -> if M07 passes,
continue remaining M15 qualification. Final M11 integrated qualification
runs against the selected model, without duplicating it against all contenders
unless a specific M15 signal requires that. M07/M11 criteria stay unchanged.

Only after these prerequisites and the owner's execution scope are satisfied
may the actual automated M15-A acceptance begin. Setup final state:
`M15_AUTOMATED_CLEANUP_BENCHMARK_READY_TO_INTEGRATE_AFTER_PRE_M15`.
