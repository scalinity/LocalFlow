## What shipped

1. **The serialized insertion queue (S18).** `InsertionService` owns one daemon thread; `_finishWithText_` only enqueues — no AX call, pasteboard write or settle sleep ever runs on the UI callback (V1 slept 50 ms inline and posted a racing 0.6 s restore thread). Completed jobs never interleave clipboard transactions: the two-queued-results test proves the op-log order publish→restore→publish→restore.
2. **Target revalidation (the M06 `same_destination` consumer, task 1).** `validate_target` runs immediately before writing on the queue thread: identity (pid/bundle — exactly `same_destination` for full snapshots), window title (the system host resolves `AXFocusedWindow` from the application element), field role, and exact-selection-only for the replacement case; a moved caret never blocks (queued results land in dictation order). `target_changed` routes the artifact to saved history with the text on the clipboard as the one-action paste offer. Unreadable window/role reads degrade to `unavailable` — identity alone governs.
3. **The method matrix with ownership generations (task 2).** Cancelled ⇒ nothing; terminal+multiline+uncertified ⇒ copy-only (`multiline_terminal_unverified` — the guard classifies the LIVE frontmost bundle when no snapshot carried a category); AX-untrusted ⇒ copy-only (V1 parity); settable `AXSelectedText` ⇒ AX replacement (clipboard untouched); else the clipboard transaction: capture generation + supported representations (text/rtf/html/pdf/png/tiff, restored as one item), publish, post, bounded settle (0.6 s; readback polls cut it short), restore only if the pasteboard still holds our generation — a user copy always wins.
4. **Readback-only confirmation (tasks 3–4).** `confirmed` requires the pre-write consistency read plus an owned-range readback equal to the text — never the clipboard. Partial reads stay `posted_unverified` (`readback_partial`, restore safe); pre-existing identical content is `match_ambiguous` — never confirms, keeps ownership so a late paste still inserts the right text.
5. **Target-bound undo + retry reconciliation (task 5).** `undo_last` (queue thread, menu-dispatched) restores exactly our revision only while the range still holds our text — a newer edit degrades to the clipboard offer; no synthetic Backspace exists. `paste_again` reconciles with capped reads (`already_present` / async `repaste_submitted`).
6. **S29.8 bounded observation (tasks 6–7, started here not in M14).** A `confirmed` insert certifies the surface; `OutcomeObserver` (default 30 s, `outcome_observation_sec`) reads ONLY the owned range, re-anchors (±400 cp, deadline-bounded) on outside edits, records in-range edits with lease-governed before/after artifacts carrying exact job/region attribution, and stops with recorded reasons (window_elapsed, focus_lost, field_changed, secure_field_transition, new_dictation [timestamped — only dictations after the window opened], session_locked, target_read_failed). The lock re-arms on wake. Uncertified surfaces report `outcome_observation_unavailable` (`unreliable_target`) and never poll. `no_edit_observed`/`undo_candidate` are never correctness labels or preferences (AC06).
7. **Store schema v4 + evidence.** Additive `insertions`/`insertion_observations` (all writes via `Store.submit`); the envelope's outcome family carries the real state machine via `on_insertion_result` (interim observation block at insert, final via `on_observation_closed`); the legacy `on_insertion` keeps the V1 semantics the M02 suite pins. Recovery menu gains Undo Last Insertion and Paste Last Result Again.
