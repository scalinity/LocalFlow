## What shipped

1. **Versioned definitions with preserved revisions (S16, AC01).** `transforms.definitions` + `transforms_store` (schema v7): built-in polish/concise/prompt_engineer contracts (content-hash prompt revisions), custom transforms with declared edit scope, optional writing samples, single-char shortcuts (collision-checked at write time; the legacy keys 1/2 recorded but never bound), target profiles and the opt-in auto-apply flag. Every edit appends to `transform_revisions` — delete disables, nothing is ever erased; the two uploaded V1 definitions materialize from the M02 legacy artifacts frozen (prompt verbatim, edits refused).
2. **The execution engine with task identity (S16/S29.10, AC05).** `TransformJob` freezes source/transform/prompt/instructions/examples; `task_key` = hash(mode, source, instructions, examples revision, prompt revision, locale). Retry-original is the same task; transform-of-result and any changed source/instructions/prompt revision are different tasks — the store refuses cross-task judgments at write time. One bounded greedy generation on the cleanup engine's loaded model in the worker (`transform` op; GPU-serialized with dictations). Paths: `applied` / `needs_review` (original clauses kept, never auto-applied) / `fallback_original` (failure, output limit, refusal — an oversized source refuses at 12,000 chars).
3. **The Prompt Engineer's requirement-atom map (S16, AC02).** `atoms.py` extracts atoms deterministically (questions, negations, edit constraints, counts, ordering, deadlines, uncertainty, quoted spans, URLs/paths) and reports three-valued coverage per atom with the output span carrying it; missing/uncertain atoms are review issues surfaced beside the diff — never silently dropped, and auto-apply declines. Every mode guards quoted spans/links/identifiers verbatim. The uploaded prompt's "relevant context"/"format if implied"/"be concise" wording appears nowhere.
4. **Selected-text execution (S16, AC03).** Status menu → Transforms (rebuilt on open) → capture (selection + snapshot-shaped target identity, off the UI callback) → generation thread → the preview panel: block diff (+ word diff for short sources), REVIEW clauses kept, Accept / Copy / Retry Original / Apply Another… / Transform Output… and an honestly-labeled Save-to-Scratchpad (M12). Accept routes through the M08 insertion queue with revalidation — a changed selection never overwrites (target_changed → copy offer). The panel is non-activating; undo of an accept is the M08 target-bound undo. The pill acknowledges immediately (MODE_TRANSFORMING).
5. **Mode executors + opt-in auto-apply (S15, AC04).** All six modes are executable; a transform-backed mode executes through its bound definition when the definition opted in AND targets the resolved profile — otherwise Clean with the honest reason (`transform_auto_apply_disabled` / `transform_profile_not_targeted` / `transform_not_bound`), visible in the menu line, the envelope and (new) the Styles rule editor offering all six modes. The dictation path transforms the **Clean artifact** after it is recorded and before finalize: Clean stays the cleanup stage's applied output, the transform writes its own stage artifacts, and only a validated result changes the inserted text. Cleanup-off honestly refuses (`transform_requires_cleanup`).
6. **Evidence + Hub (S29.4, S19).** `on_transform_result` retains the exact prompt/output lease-governed and fills the content-free envelope `transform` block; `note_transform_gate` carries requested-but-not-run reasons; History's fourth lineage stage resolves from `transform_output` artifacts. Store v7 adds `transform_candidates`/`preference_observations` (rows id/hash-only; texts in artifacts inside the same writer op; display order ranks candidates within a task). The Hub Transforms view (VIEWS 7→8) rides the `_build_/_refresh_/_load_` triple with `transforms_service`; Scratchpad/Insights still refuse at state level.

- **Construct NSObject surfaces the way production does, and test that path:** the review-C1 lesson now has a second worked example — the pipeline test constructs the panel through `_tfShowResult_` (`alloc().init_panel`), not by calling the coordinator action directly.

- **Task identity for preferences:** hash every input that defines the task (mode, source, instructions, examples revision, prompt revision); enforce same-task at write time; record display order within the task.

### What changed

- **Requirement gate (01, 02, 04, 12) and serializer (03), shipped together.** `atoms.py` now treats every source clause as a requirement with an operator profile (negation, hedge, condition incl. soft conditions like "if they exist", scope, alternative, interrogative, sequence, directional relation, stop, always, comparators, numbers bound to their noun) and governed words. Prompt Engineer needs the clause's content (⅔ of its stems, all when ≤ 2) in one output segment — or a short run of adjacent segments for clauses with ≥ 4 stems and pure ordering clauses — with every operator holding there; ties between equally good segments that disagree on negation/hedge are uncertain; every source stem must survive. Polish and Concise get the operator/invention/exact gate without the content threshold (their own contracts demand it and their auto-apply exposure is the same); Custom keeps exact carry only. Invention checks catch added governing operators, S16 escalation terms, novel numbers and identifiers. Exact carry covers any-length quotes, single quotes, backticks, fences, cleaned URLs, rooted/relative paths with spaces, any-extension files and identifiers, case-sensitively with alphanumeric-edge boundaries. `Coverage.to_json` reads the atom's kind; the worker round trip and a portable parent-side rebuild (`engine.result_from_message`) carry coverage and the `validator_revision` (`m11-gate-2`). Review excerpts are de-duplicated.
- **Oracle (05).** `test_prompt_engineer_cases.judge` is independent of `atoms.py`: relations checked inside one output segment, negation-aware forbids, intent escalation, and seven separate verdicts (a fallback can never print as applied; the run fails on fallbacks unless `--allow-fallback`). Fixture **v2** marks the ten v1 held-out cases exposed (split `regression`) and adds ten blind families (`PE-BLIND-001..010`) written before the gate and never run against it here; v1 is unchanged.
- **Evidence (08, 09, 10).** `TransformStore.record_candidate` writes only under collection consent — read inside the writer op for previews (revocation during generation honoured), the job's captured consent for dictation — and returns `None` otherwise; the transform still works. Candidates keep `transform_prompt` and `transform_decision` children of the output; note sources record `note_id`/`note_revision_id`; the dictation collector writes the decision artifact and the envelope carries the validator revision. Retry Original records no rejection; the new candidate carries `retry_of`. An accepted selection's insertion row is attributed to its candidate id. The M14 transform export adds `automated_path` and `decision_artifact_id`.
- **Destination authority (06, 07, TG-03, TG-04).** `insertion/selection.py` classifies the field first (a secure field refuses before any read) and records window title and 200 characters either side; `validate_target` has a strict-replacement mode (set only by transform accepts) that needs positive proof of title, role, selection and surroundings. Plain dictation is unchanged (pinned by a control). Note transforms carry an immutable destination `{note_id, revision_id, range, text}` checked by `notes.note_destination_check`; chained Transform Output keeps it; the Scratchpad converts UTF-16 `NSRange` to code points.
- **Panel (11).** Buttons are laid out side by side (`action_frames`); the widest row fits the 460-pt minimum.
