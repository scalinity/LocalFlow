## What shipped

1. **The faithful-contract prompt (Spec S13).** `prompts.CONTRACT` is the S13 clean-prompt contract verbatim; curated examples satisfy the contract themselves (digits stay digits, the exact `/code-review` token, retained questions, cloud stays cloud, "like"/"you know" are content, Spanish stays Spanish). The prompt is versioned by content hash (`m07:<sha256-12>`); instructions stay separate from payloads (system = contract, examples = few-shot turns, final user message = the S13 structured JSON fields). Sampling is explicit and recorded: greedy (`make_sampler(temp=0.0)`), `enable_thinking=False` retained, `max_tokens = min(words*3+96, 4096)` (corrections 160), template hash recorded.
2. **Complete-block windows (S13 long utterances).** The 35/50-word chunker is gone: a dictation within 200 words is ONE generation; longer input packs whole paragraphs/list-groups/code-fences into windows (a block opening with a correction marker packs with its predecessor; oversized blocks split at sentence boundaries never adjacent to markers). Ownership is exclusive, exhaustive and verbatim over zero-based half-open code-point ranges (fuzz-pinned over 150 randomized documents); neighboring context rides only as the labeled read-only `read_only_context`.
3. **Offset-exact corrections (S13).** A separate proposal pass only when markers are present, in V1's production-proven line format; every span resolves to exact offsets by sequential in-order matching (duplicate spans delete in spoken order; offsets stable under Unicode case folding via `re.IGNORECASE` on the original text); deterministic guards (marker-terminated, no bare markers, ≤6 words, ≤6 applied, protected-span and overlap rejection with recorded reasons); deletions apply in Python so the surviving replacement and reason clause stay by construction.
4. **Validation with an explicit deterministic/heuristic boundary (S14, E09).** Ten components; deterministic failures (coverage with flagged deletion ranges and question flags, numeric values — a valid word→digit representation passes while 30→300 fails, protected tokens, literal spans, negation and uncertainty multisets, technical tokens, novelty, explicit-structure counts) reject the candidate; heuristic findings (names, spoken-enumeration counts, clause association) are labels only. Authorized deletions are explicit: corrections (applied before validation — the validation source is the corrected text, never stale offsets), fillers, stutter/doubled prepositions, phrase-initial interjectors, number-word representation changes whose value survives, vocabulary alias→canonical pairs, spoken-list markers when a list is rendered (values carried by the rendered numbering, including seam-continued numbering), `equals`→`=` symbol rendering, `a`/`an` article adjustment, and hyphen/contraction-equivalent word atoms.
5. **Termination, recovery, fallback ladder (S13/S14).** Output-limit detection from the generation token count; recovery halves the ORIGINAL source range at a sentence boundary and retries (sub-windows are fresh windows — AC02-safe); a failed retry ships the window's normalized source with `incomplete: true`, `termination.kind: "output_limit"`, path `llm_partial` — a truncated output is never pasted as success. Per-window ladder: validated clean → normalized source (corrections roll back with it, M07-AC02) → job-level basic/raw with M03's exact honest labels (`llm_fallback_normalized`, `basic`, `cleanup_engine_failed`).
6. **Document nodes (S13).** Paragraphs, ordered/bulleted list groups, code fences; the renderer — not the model — controls numbering and separators; seam-continued lists renumber contiguously; structure facts feed validation and evidence.
7. **Permitted context (contracts/context.md).** Cleanup receives exactly: per-window protected spans (the M04 ledger's zones mapped raw→normalized by verbatim search, rebased per window), the job's frozen vocabulary canonicals (≤40, engine-enforced) plus frozen alias→canonical pairs as validator-only data, the destination profile from the M06 snapshot's target category, locale and mode. Nearby text, identifiers, origins and workspaces never reach any cleanup prompt (invariant pinned through the real coordinator).
8. **Evidence (S29.4 cleanup family; S29.14).** Per-pass observations (exact rendered prompts, inputs, outputs, token counts, limit flags, window ranges) ride the M02 prompt-dedupe artifact mechanism; rejected candidates keep their `cleanup_rejected_proposal` role beside the intact fallback (M07-AC05); the exact permitted-context payload is a lease-governed `cleanup_context` artifact; the envelope's `cleanup.v2` block is content-free (prompt version/revision, template revision, sampling, termination, window source ranges joined to raw coordinates through the normalization ledger, validation outcomes, fallback lineage). Validator outcomes are mining signals only — `outcome.correctness` stays `unreviewed`, no preference inferred (M07-AC06). Verbatim (raw) and intended-writing (applied) references stay separate artifacts with source-range coverage maps for later supervised exports.
9. **Selection + config.** `cleanup_implementation: "v2"` (default, on the ablation evidence below) | `"v1"` (the untouched TranscriptCleaner control, kept for the ablation and as fallback). A failed V2 load degrades through the basic TranscriptCleaner with M03's exact labels.
10. **Fixtures (EV-09).** Exactly 60 fidelity + 40 structure + 20 literal synthetic post-normalization fixtures under `tests/v2/fidelity/` and `tests/v2/structure/` with an `m07_created` manifest block; the four multi-window structure fixtures (206–226 words) pin list survival across seams.

## Limitations / unresolved

- Documented in `contracts/cleanup.md`: a correction straddling a block seam applies only when the marker-open packing rule keeps both sides in one window — the residual case falls back losslessly (uncorrected source), never corrupted; validator sentence/question flags and name checks are heuristics on unpunctuated ASR text (findings, never gates); `WINDOW_MAX_WORDS=200` is a measured constant, not a knob; the real-text stratum awaits human review.
- Per-process near-tie instability on the 4-bit model: greedy decoding is deterministic within a process but borderline token choices (hyphenation, punctuation) can differ across processes — the fixtures' assertions are hyphen/whitespace-tolerant where the difference is representational, and every deterministic safety check is process-independent.
- The installed /Applications app still runs pre-M02 code (no build authorized); M07 exists in dev runs and tests.
- Unknown from M01–M06, unchanged: producer source of stats/dictionary/transforms; `instance.lock` producer; the M01 release-to-insert pilot (M15 gate).
