All writes guarded: an analytics failure is one content-free event and never disturbs dictation (pinned by a raising-store test through the real pipeline).

## Reusable patterns for M14+

- **Facts denormalize what aggregates must survive:** usage_facts carries its own app/duration/word copies because content and job rows expire on their own clocks — any M14 surface that must outlive content retention should copy, not join.
- **Derived tables are recomputed, never incremented:** the day's aggregate is rebuilt from its facts inside the same writer op as every mutation, and a writer that moves a row between days recomputes both — the drift class the review caught is structurally closed by the same rule (plus the invariant test).
- **Retry provenance from the store, not the clock:** a re-run of an existing logical entity reads its original instant/zone/app from the store rows; "now" is never a substitute for a lost instant (the refusal rule does the refusing).
- **One cohort per number:** a metric's value and its displayed denominator must be summed over the same WHERE clause — the WPM defect was two populations in one label.
- **Honest-coverage denominators:** a coverage metric's denominator must count the population that COULD fail (every named reference), or it is a tautological 100%.
