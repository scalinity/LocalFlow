## What shipped

1. **The vocabulary domain (Spec S11, EV-07).** `localflow.v2.vocabulary`: the entry model (canonical, language, kind term|skill, matching mode, scope, priority/pin, usage, origin, enabled/approved, verification label `explicit|context_supported|suggested`, per-entry revision, per-alias approval); five scopes (global/app/site/profile/workspace) with deterministic precedence workspace > profile > site > app > global; the immutable `VocabularySnapshot` (approved+enabled+in-scope match index over explicit aliases plus each entry's own canonical for case preservation — `mlx` → `MLX`; same-scope collisions masked and surfaced as conflicts, never resolved by insertion order; content-hashed `m05:` revision); `sandbox_phrase` and `preview_entry_conflicts` for the UI.
2. **Engine integration (layer 5, contracts/normalization.md).** `grammar_vocabulary` in the M04 engine: token-boundary phrase matching on token cores (edge punctuation survives), longest-valid-phrase within the layer, already-canonical spans emit nothing and claim the span (idempotence shield against shorter-alias drift), blocked in quote/escape zones, URLs safe by tokenization. Every proposal carries `rule_id` (approving entry) and its verification label — additive `rule_id` field on Proposal/EditRecord/RejectedProposal, JSON round-trip tolerant of old ledgers. Dictionary-scoped skills populate `registered_skills`, closing M04's inert unknown-skill gap. `grammar_identifiers` received the same token-core span fix.
3. **Persistence (store schema v3, additive).** `vocabulary_store.VocabularyStore` over the single-writer store: versioned entries with append-only history and a state counter; one-canonical-per-scope enforced case-insensitively (caller-thread probe with content-free errors + NOCASE unique index); the seven legacy terms adopted from the M02 legacy artifacts; Claude/Claude Code seeded as visible unapproved profile-`coding` suggestions that never rewrite text until approved and stay dismissed once disabled; idempotent JSON import/export that never fabricates usage; `record_hits` for applied matches (approval checked at match time under the frozen revision; usage excluded from invalidation so hits never force rebuilds). `Store.submit(fn(db))` is the sanctioned writer-thread entry point; the torn-write repair path covers the v3 tables.
4. **Pipeline wiring (app.py).** At hotkey-down — after the overlay shows, so selector work never delays visible feedback — the app freezes per job: vocabulary policy (dictionary skills registered), context (snapshot in `ContextSnapshot.vocabulary`) and a HintSet; in-flight jobs keep their revision across edits (AC03, tested live mid-flight). Applied approved matches record hits after normalization; the coordinator uses the job's captured policy/context. A store failure degrades to vocabulary-off with an event — never a startup crash, never a dropped dictation (tested).
5. **Hint sets and the selector (S30.1, EV-18).** `RelevantVocabularySelector` ranks pin → scope → recency → frequency → priority (ties by entry id; order precomputed at snapshot construction) and emits an immutable `HintSet` (ordered terms with scope/source/score — a score, not a probability; budget omissions with `budget_limit`; content-hashed id; `hint_term_limit` config, default 100). Frozen pre-decode and stored before recognition when collection is enabled — later corrections never relabel original hints (S29.11). `hint_disposition(manifest, hint_set)`: offered-but-ignored under the still-unqualified adapter (zero offered ⇒ nothing ignored — honest false/null); `asr_hint_request_fields` returns None until an adapter+checkpoint+runtime is separately qualified (the extension point; its future shape pinned by a synthetic-manifest test). Post-ASR repairs are ledger edits with rule ids, never decoder hits.
6. **Evidence (S29.4 context family).** `on_hint_set` writes the frozen set as a lease-governed artifact pre-decode and fills the envelope's `context` block (ids/revisions/counts/disposition only); the normalization block gains `vocabulary` (snapshot revision + applied rule ids). Failure to retain emits an event.
7. **Management surface.** `localflow/v2/dictionary_panel.py`: a deliberately simple AppKit panel (search, numbered listing, add-with-conflict-preview, approve/disable/pin/delete, phrase sandbox with scope-labeled suggestions) over the public store APIs — reusable by the Hub (M09). Menu: Dictionary…, Import/Export Dictionary JSON…. Construction is smoke-tested; interactive use is the pending human check.

## Contracts and decisions

- New `contracts/vocabulary.md` (entry model, scope precedence and conflict masking, snapshot semantics, matching rules, store schema v3, HintSet/selector, consumers, evidence, management surface, documented limitations, M06 dependencies). `contracts/INDEX.md` row + decision note; `contracts/store.md` M05 additions; `contracts/asr_hints.md` M05 live status; `contracts/training_evidence.md` context-family live status; `contracts/normalization.md` layer-5-fed status. No frozen identifier changed; registry unchanged (33/22); no ADRs — no spec deviation accepted.
- **How the dictionary feeds the policy (settled, per the kickoff):** the app rebuilds `NormalizationPolicy` and the context only when the store's revision counter changed (skills hash into `policy_revision`; terms flow through the immutable per-job snapshot), and captures the trio into the job at hotkey-down — construction is per-dictation-cheap and cached, in-flight jobs hold their frozen objects, and AC03 holds by object identity rather than snapshot invalidation.
- **Usage is ranking statistics, not matching state:** `record_hits` does not bump the state counter and the snapshot revision hash excludes usage — an applied hit never forces a snapshot rebuild; selector recency/frequency see the last-edited snapshot. Chosen to keep hits off the hot path (a 10k-entry rebuild costs ~125 ms).
- **A lone approved wrong entry rewrites its own alias** (measured in the matrix: distractor flips 40/40 under distractor-only); the protection is same-scope masking when the true term exists. An approved rule does what it says — reported, never hidden.
- **Pre-M06 scope honesty:** the live app filters with no destination context (global entries only, hint set offers global entries only); workspace/profile/site/app resolution waits for M06. The sandbox labels out-of-scope suggestions rather than advertising rewrites that cannot fire.
