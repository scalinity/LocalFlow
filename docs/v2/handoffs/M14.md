## Checkpoint records (M14-A / M14-B / M14-C)

The three checkpoints were implemented in one pass and are recorded together here (M14-AC10).

- **M14-A: labels and review.** Contracts: `learning.md`. The multi-axis S29.7 classifier abstains honestly (`unchanged_output`, `not_target_bound_rewrite`, `unclassifiable_region`, `negation_flip_needs_review`). Correction labels are per-example, append-only and axis-validated. Grafts must index the raw source and stay `coverage_kind: partial` forever. A shared ASR promotion gate requires a live state, an audio-reviewed verbatim reference, retained audio and no changed-intent/ambiguous/user-rewrite label. The learning candidate has three producers (teach, M08 windows, single-dictation note edits). Suggestions are ASR-origin recognition errors only; approval composes with M05 entries, runs scoped counterexamples first and records a plan so undo reverses exactly what it did; rejection is permanent. Fixture results: 100-record pack + 40 negatives, zero negatives promoted, suggestion gate 5/5 on synthetic fixtures (mechanics, not accuracy).
- **M14-B: sampling, preferences and splits.** Contracts: `learning.md` (sampling), `preferences.md`, `dataset_exports.md`. Sampling is a seeded 10% Bernoulli stream plus explicit, hard-trigger, supplemental and late-trigger strata, with null probabilities for enriched selection and one inclusion per example per policy. Pair review covers A/B/tie/neither/uncertain, slot A = `candidate_id`, the latest judgment wins, and the store's same-task invariant enforces it at write. Family splits are versioned and deterministic (80/10/10) with a 10-family floor; exposure is forward-only and permanent, and tags stay independent of partitions.
- **M14-C: export, readiness and profile.** Contracts: `dataset_exports.md`, `profile.md`, `hub.md`. Five task views and an offline validator. Readiness fills split contamination, export integrity, nearing-expiry, and verbatim coverage in reviewed seconds. Your Voice: eligible-evidence measured views, cards citing their own supporting examples, snapshots as records, deletion clears derived text, chunked reads, and an idle pass that skips unchanged evidence.
- **Collection start and coverage (live store, read-only count):** consent enabled; 10 jobs, 6 training examples (5 `captured_unreviewed`, 1 `excluded`), 0 edit observations, 0 transform candidates, 0 preference judgments, 0 labels. Every M14 floor is unmet on real data — splits stay unassigned, no candidate, no pair, no card — which is the valid measured-only state, not a gap to fill with invented labels.

## What changed in this session (audit, then review loop)

**Semantic review** of the inherited code found more than thirty real defects, all repaired with regression tests (full list in `results.json` → `semantic_review`). The most consequential:

- the exporter `rmtree`d any existing destination folder;
- `prefer_b` exported the rejected candidate as chosen;
- the Hub's action wrapper took no keyword arguments, so Approve, Reject, Label and Export failed on every click;
- re-assigning splits hashed exposed families back into `frozen_test`;
- approval failed for any canonical already in the dictionary;
- the counterexample check was vacuous for app-scoped rules;
- stage attribution read the wrong keys, and read the normalization ledger JSON as if it were text;
- the idle pass minted a profile snapshot every 30 minutes forever;
- profile cards cited arbitrary examples, and hours were UTC;
- invalidated snapshots kept phrases from deleted speech.

Profile compute and mining now run in short chunked ops. The worst dictation write delay dropped from about 235 ms to 45 ms during profile compute, and to 1 ms during mining.

**/review-2 → /address.** Two read-only reviewers ran on Fable. The verdict was Request Changes, with 3 criticals (plus 10 warnings and 10 suggestions):

1. Deletion missed job-keyed and note-sourced candidates.
2. Transcript words sat in candidate rows, and every mined candidate carried a never-expiring lease that pinned its whole job past the unreviewed buffer.
3. Labels resurrected quarantined or expired examples into live states.

Every finding was addressed with tests; no findings were rejected as incorrect. While fixing them I found three further latent gaps: `classification_json` also carried region words, the queue hid job-only teaches, and the export CLI migrated the store without a backup. One suggestion was decided without code change: the export snapshot stays a single writer op, because S29.13 requires a consistent source snapshot (measured worst dictation wait 50.6 ms at 10k examples, and export is a user action). Full record in `results.json` → `review_loop`.

## Reusable patterns for M15+

- **Propagate by the key the data actually has.** Learning candidates are job-keyed because a teach with collection off has no example. Deletion, expiry and note deletion each reach them by that key.
- **Rows hold offsets; artifacts hold words.** Anything text-bearing lives in a lease-governed artifact, so deletion and expiry have exactly one place to remove it from.
- **Unreviewed machine output never pins retention.** Only reviewed evidence takes a never-expiring lease.
- **Record the plan before the side effect.** Approval persists its entry id and action first, so an interrupted operation resumes instead of orphaning.
- **Chunk reads for idle work; re-check liveness in the one write op.** A deletion mid-read restarts the computation rather than recording dead evidence.
- **Measure the writer hold with a continuous probe, not a single sample.**

## M15 qualification inputs

- **Views and sizes:**
  - `asr_supervised`: input is the original float32 mono 16 kHz WAV clip (≈64 KB/s, clip-level, no alignment); output is the audio-reviewed verbatim text.
  - `cleanup_supervised`: input is the normalized text plus every rendered Qwen3-4B prompt the stage sent; output is the applied text marked intended-correct.
  - `transform_supervised`: input is the source text plus the frozen transform definition; output is the accepted output.
  - `preference_pairs`: the same-task input hashes and two outputs with their display order.
  - `asr_span_graft_weak`: grafted text with coverage spans, weak and partial.
- **Eligibility settings:**
  - the ASR gate above;
  - explicit intended-writing mark (cleanup), `accept` (transform), comparable judgment (preferences);
  - splits need at least 10 live families (80/10/10, seed `localflow-m14-splits-v1`);

  - profile floor: 2,000 words and 10 dictations.
